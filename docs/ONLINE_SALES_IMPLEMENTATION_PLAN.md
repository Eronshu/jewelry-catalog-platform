## 3. 发布、支持和硬门槛

以下事项不能靠“上线后补”替代：

- **账户与金额：**两家必需支付渠道完成实际 Sandbox；正式资格/配置另核对；税费、运费、退款规则有经营依据和算例。仍有 unknown 付款/退款必须可查可接管。
- **库存与履约：**真实 SKU/颜色和尺寸已核对盘点，缺货不可购买，处理/交付区间已批准；FB 留量有实物标记和最小登记办法；多行原子性、迟到付款、渠道调拨与验收入库测试通过。
- **隐私与安全：**演示与正式隔离，Admin/查询/导出权限、密钥轮换、日志脱敏、消息收件人限制已验证；不得用正式数据做作品。
- **运营：**小姨完成真机 UAT；你确定预算和支持/替班；告警实际触达，恢复与停收新单演练有证据；公开政策和联系渠道完备。
- **上线：**本轮无任何部署授权。之后需明确发布范围、负责人及失败停止条件；生产回滚保留订单/账本，并继续接收事件和处理既有顾客。

首批订单阶段：小姨每日检查新付款、盘亏/配送延误、待交付、退款与通知异常，并核对服务商交易；按实际结算周期核对银行。开发者每日检查事件/任务积压、错误和告警，直到双方约定的稳定条件达成再降低频率。之后仍保留每日经营对账、定期库存盘点/备份恢复演练、依赖安全更新及供应/政策复核。具体响应时限、稳定观察期和维护频率在 D07/C16 定稿，不凭空承诺全年全天值守。
