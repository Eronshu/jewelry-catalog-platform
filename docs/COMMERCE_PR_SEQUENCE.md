## 每个 PR 的交付与停止点

1. 从更新后的 `main` 建功能分支，复用本组原始提交，明确 PR 的依赖、范围、测试证据和剩余限制。
2. 执行格式、lint、typecheck、测试、生产构建；支付、库存、退款和权限变更还需审查异常路径。失败则修复当前 PR，不混入下一任务。
3. 提交并开 PR，等待远程 CI 和审查；审查请求、结果与实际 head SHA 对应。CI 通过不能代替审查，自己的总结不冒充独立批准。
4. 检查未解决审查项与最新 head 的 CI 后合并当前 PR，再更新本地 `main`；保留完整备份分支。若审查待完成或服务受限，停在当前 PR，不开启下一分组。

四个 PR 均合并后，才从更新后的 `main` 建 `codex/commerce-c09b-delivery-quote`。建分支不代表本次开始 C09b；下一小任务仍须独立提交/PR，不能堆回备份分支。

## 停止与回滚

未合并时保留 PR/分支供审查，不改写备份。已合并变更有问题时，以新的修复或 revert PR 处理，保留审计记录；数据库相关回滚保留订单和库存账本，不清表或执行破坏性降级。第 1 个 PR 只有未接线的本地工具和纯函数，回退无需数据库操作。
