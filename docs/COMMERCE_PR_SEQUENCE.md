## 每个 PR 的交付与停止点

1. 从更新后的 `main` 建功能分支，复用本组原始提交，明确 PR 的依赖、范围、测试证据和剩余限制。
2. 执行格式、lint、typecheck、测试、生产构建；支付、库存、退款和权限变更还需审查异常路径。失败则修复当前 PR，不混入下一任务。
3. 提交并开 PR，等待远程 CI 和审查；审查请求、结果与实际 head SHA 对应。CI 通过不能代替审查，自己的总结不冒充独立批准。
4. 检查未解决审查项与最新 head 的 CI 后合并当前 PR，再更新本地 `main`；确认无遗漏并按授权清理已合并分支，未整合内容先归档。若审查待完成或服务受限，停在当前 PR，不开启下一分组。
