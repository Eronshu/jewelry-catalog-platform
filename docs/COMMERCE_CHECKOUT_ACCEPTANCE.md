# 本地虚构最终报价与接受记录（L04a）

日期：2026-10-29。Issue #63，从 #62 / main `131e678`（准确head CI96、独立审查及main CI97通过）开始。本片是内部fixture服务端模型，不是顾客结账入口或付款许可。C路线和冻结V1不变；实际检查结果见 [执行记录](./COMMERCE_EXECUTION_LOG.md)。

## 范围与信任边界

既有 `/checkout` 和 `/checkout/quote` 仍只返回临时报价，不保存输入资料或创建订单。旧lab的 `commerce_quotes` / `commerce_orders` 使用 `local-test-v1` 零税契约；新顾客费税快照不能直接交给 `reserveTestOrder` 或旧付款开始模块。

本片新增独立的最终报价和接受记录，不改旧表、库存、订单、支付状态、路由或本机runner。接口只接受预设fixture资料标识，服务端映射合成姓名、`example.invalid`邮箱和虚构地址；不接受任意姓名、邮箱、地址或Google结果。这样限制的是本片输入，不能据此宣称未来真实资料的留存、删除和隐私政策已经完成。

可信调用方提供 `mode=local-test`、实例ID及owner哈希，所有键和读取都带完整分区。它们是**行级分区，不是数据库归属证明或浏览器认证**；本片没有HTTP消费者。未来接入页面前仍须独立绑定验证、可用性/同源/CSRF、专用游客凭据和限流，不能直接把请求字段当作可信context。

## 两种命令

| 命令         | 输入与结果                                                                       | 不变量                                                                                     |
| ------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 发出最终报价 | 独立issueKey、规范化选购、fixture资料和交付方式；服务端分配quoteId并计算完整报价 | 不接受金额、税率、币种、owner或期限覆盖；数量/变体/名称/价格、交付与固定虚构规则保留快照   |
| 明确接受报价 | 独立acceptanceKey、quoteId、同一选购及明确同意                                   | 首次接受核对owner/实例/原快照、期限、当前商品/库存及固定规则；接受收据不能当订单或支付凭证 |

现有UI的requestId只是临时请求关联；不因为它是UUID就赋予持久接受权限。命令键分开使用。同一原键、原内容重放原收据，期限、价格或库存后来改变不篡改历史；复用键修改内容冲突。另一个接受键不能为同一报价制造第二份接受。

规范化输入在第一次await前检查并复制；未知字段、访问器、非普通对象、异常数组及非法数量/ID拒绝。对外结果和错误不带顾客资料、owner或数据库错误。内部fixture存储也不得用于实际顾客数据；哈希不等于匿名化。

## 金额、规则与并发

固定虚构交付规则沿用测试费税：10%仅为故障测试算例，**不是加拿大税率判断**；自取0、本地送货500分、邮寄1500分也不是经营承诺。处理采用CAD整数分、安全整数边界和明确舍入。10分钟报价有效期是fixture假设，不是留货期限或交付保证。

发出报价和第一次接受各自在写入时再次核对数据库中的发布/启用、SKU/名称/颜色/规格、版本/价格及网站可售量（实物减FB留量、临时预留和已分配）。产品名称没有variant版本保护，不能只比较版本。有效区间为 `issuedAt <= acceptedAt < expiresAt`，恰好到期拒绝；在异步准备完成后重新采样时钟。

规则目前是固定JS描述，保存其快照/指纹作为应用侧见证。SQL不能仅凭绑定进来的哈希证明独立的“当前规则库”已经核对；本片不建立可编辑规则注册表。未来经营规则变更需单独版本化设计和测试。

**接受不锁库存。** 两个顾客都可接受最后一件的报价；只有后续订单/预留事务才能决定谁实际获得库存。L04b必须原子重验金额/期限/完整绑定与全部行现货，不把接受收据当永久库存许可。旧订单/付款/事件保守闸门保持原样。

## 验收与停止

验收包括真实临时D1迁移升级、三种交付、金额/数据边界、同异键重放、跨owner/实例拒绝、到期边界、商品名称/价格/状态/库存变化、并发和丢响应恢复、直接SQL保护、事务失败无部分记录及旧订单/库存不变。具体通过结果只在实际运行后记入日志；本片没有浏览器UI变更，不能提供iPhone Safari/VoiceOver或服务商Sandbox验收证据。

回退停止调用新内部命令、回退兼容代码；保留新增表、原快照与收据，不删除记录或运行破坏性降级迁移。当前没有HTTP入口可关闭，也没有真实收款或库存占用需要补偿。迁移只在独立临时库测试，不向生产执行。
