# 本机异常订单关注中心

Issue109 的只读经营入口为 `/admin/commerce/attention`。它将同一权威 owned 订单的待核付款、未确认退款和模拟通知待办放在一起；不会调用服务商、重新扣款、退款、投递或释放库存，也不是银行结算对账或实时服务商健康保证。

## 开启与操作

在现有本机虚构商城启动命令中设置 `COMMERCE_LOCAL_ATTENTION=1`。runner 仅向本机 Worker 注入 `COMMERCE_OWNER_ATTENTION_UI=local-test`，默认关闭，无新增凭据。入口仍需要已批准的 Admin、精确 local-test 实例和 loopback origin，权限/配置验证先于数据库访问。其他退款和通知入口由各自开关独立控制。

经营者可选择全部、付款、退款或模拟通知，或输入完整订单编号精确查找。每页最多25单，下一页沿用同一分类和编号；切换分类/编号重新开始分页。顶部数量按同一读取快照统计独立订单，分类可以重叠，数量不受当前页影响。页面显示本地读取时间；刷新只重新读取本地记录。

- **付款待核：**有效 attempt 尚缺可信 canonical 收款证明，或 PayPal 记录了后续负面事件。保留原键和库存，使用已有订单入口人工核查；这里不把回跳、批准、事件或派发回执当付款结果，也不推断已经失败。
- **退款待核：**同原 capture 的退款意图尚无完整确认事实。原请求、可退预算和履约锁保持，使用现有退款入口找回原请求，不能换键重退。
- **模拟通知：**权威 capture/refund/pack/handoff 来源尚未准备，或已有意图等待/模拟失败。最多3次的耗尽状态单列；撤销和模拟送达为终态。过期待办仍需人工关注，不暗示链接可继续使用。这里没有真实邮件。

空列表只表示当前分类和实例没有匹配记录，不能证明支付已经实时核对或可以履约。

## 数据与验收边界

查询为 GET-only；稳定有界游标绑定模式、实例、原 origin、分类与精确订单编号。只读投影排除旧 lab、其他实例/原 origin 和伪关联；不返回顾客联系资料、服务商秘密或原始 capability。响应为私有 no-store、no-referrer/noindex；错误正文静态，不回传 SQL 或任意异常。

本片没有迁移、后台任务或新账本。测试使用虚构隔离 D1，覆盖付款/退款/模拟通知状态、重复观察、分页、作用域隔离、无写入及 Worker→Router 权限。浏览器表现检查与实际 Admin 身份认证、Mobile Safari/VoiceOver、经营者 UAT 分开记录。原真实 Sandbox 付款、退款及未知订单状态不为本片开发而变更。
