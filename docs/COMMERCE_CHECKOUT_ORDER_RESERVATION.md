## 为什么复用订单根

[最终报价接受模型](./COMMERCE_CHECKOUT_ACCEPTANCE.md)只证明对不可变虚构报价的同意，不占库存。旧lab的零税 `TestQuote` 不能直接当新报价使用；但0009以后支付尝试/work/事实的外键和查询都引用既有 `commerce_orders` / `commerce_quotes`。再造平行订单表会迫使后续复制支付链路或重做大量关联。

本片采用**显式来源桥接**，沿用现有订单、订单行和库存账本作为权威。新增不可变来源映射保存完整mode/instance/owner分区、createKey/请求哈希、原接受记录及共享quote/order/command身份。映射是来源与幂等依据，不是第二套订单状态，也不改变已选C架构或冻结V1。

原0017报价仍保存必要合成资料；提升到共享报价的内容必须等于原快照去掉 `fixtureProfile` 后的明确投影，避免再复制姓名/邮箱/地址。价格、税费、币种、规则版本、商品/选项和到期时间不改写成lab的零税值。真实PII生命周期和Google留存核对仍是未来门槛。

## 来源隔离先于新订单

- 新服务只接受可信context和 `{createKey, acceptanceId}`，不接受浏览器金额、商品行、期限、渠道或库存动作。context仍只是行分区，不是数据库归属证明或浏览器认证。
- 旧lab读取/列表、到期扫描、Admin核对/恢复和旧付款开始路径排除新来源；不把新快照盲转为 `TestQuote`。新路径必须通过完整来源映射授权，owner哈希相同不能跨实例取单。
- SQL同时防止有新契约的快照绕过映射，冻结新订单商业身份，拒绝旧转换/恢复直接处理新来源；不能只靠应用层过滤。
- 0017原快照、接受记录及0009–0016付款历史/保守闸门不变。现有lab行为保留，新增来源不会悄悄出现在旧UI或本机到期驱动器中。

## 一个数据库原子边界

创建命令使用一个来源映射INSERT触发完整事务：核对原接受和报价、创建共享quote/command/order、从保存的全部报价行生成原订单行。既有 `commerce_line_reserve` 已生成预留流水，不能再手动生成第二组。

数据库在提交前验证完整行/流水覆盖：位置、变体、数量、单价、版本及command归属完全对应。任一行缺货、版本/价格/名称/发布变化或约束失败时，映射、共享报价、command、订单、行、流水和余额一起回滚，不留下半车预留。来源专用守卫阻止之后追加额外订单行或在原command下追加库存动作；库存余额另保护新来源占用下限，防其他command的release/allocate偷走已映射预留，同时允许旧lab释放其自身份额；未来owned释放需经专门审查原子降低该下限。不重构无关库存命令。

首次创建在准备完成后采样时钟，满足 `acceptedAt <= createdAt < originalQuote.expiresAt`，并在INSERT处重验当前固定规则见证、SKU/名称/颜色/规格、价格/版本、发布/启用和网站可售量。FB留量、其他预留及已分配不参与出售。预留不得借创建新订单延长原报价有效期；期限仍是fixture假设，不是经营承诺。

规则继续是私有固定JS描述和应用侧见证，不声称SQL自行核对可编辑政策注册表。每份接受只对应一个订单；同一原createKey/原接受重放原收据，失去响应不换键重新占库。复用键换接受或为同一接受另造键冲突。成功历史重放不因后来价格、库存或时间改变而篡改；它也不代表现在仍可付款。

存储结果不明返回通用unavailable，按原键恢复；不把读取故障当作没创建订单，也不让内部SQL/资料出现在错误中。

## 本片明确不激活的能力

这次只创建**内部虚构、尚未付款的预留订单**，不接路由、页面、本机runner、游客会话、通知、付款发起或履约。共享订单根不等于旧付款API已支持新报价。

后续支持新规则必须有单独审查的迁移：0009的 `commerce_payment_attempts.rules_version` 是表级 `local-test-v1` CHECK，还存在JS验证及零税SQL守卫，不能只改一个trigger或改名绕过。本片全部保持关闭，之后复用已有attempt/work/facts，而不是复制第二套支付日志。

**独立的经营/HTTP消费者必须等待相邻的owned取消/到期释放PR。** 本片新来源不允许旧lab释放，内部测试预留到期后不会自动归还；仅在临时fixtures中创建，不能因此启用可运行商店。下一片须提供完整scope/原键、全部行一次释放、取消/到期竞争、重放/未知结果和审计，并继续禁止对processing/unknown付款盲目释放。实际支付、顾客凭据、身份/CSRF、隐私和经营门槛仍在其后。
