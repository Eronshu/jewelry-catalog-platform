# ADR-001：后续商业阶段选择 C

**记录更新：2026-10-18 · 状态：用户已选定方向；细节待设计审查，商业功能尚未实现。**

## 决定与理由

保留现有 React Router / Cloudflare Workers 网站及受保护 Admin，沿用 D1/R2，新增自有购物车、订单、库存和运营流程，使用 Stripe 与 PayPal 托管支付。作品展示与真实营业并行，环境、数据、凭据与通知隔离。该决定不授权本轮实现、商家账户操作或生产部署。

选择 C 是用户对定制体验、完整工程成果和未来经营的共同取舍，不是因为已经证明 Shopify 不适用。根据固定款业务，建议按一个收货/履约地点、简单收货验收和人工异常处理控制首版范围；不建设多仓 ERP、自有支付处理或完整会计系统。托管支付只外包支付环节，订单正确性、库存及日常运营仍由项目负责。

### 2026-10-18 首版范围收窄

用户决定缺货暂不可购买；颜色以金色、银色、黑色等为主，基本单一尺寸。C 架构不变，首版取消缺货收款、接单上限、混合待补订单及其供应分配模型。Facebook 完整订单流程暂缓，仅保留独立留 1 件及最小库存售出/调拨；按指定颜色/SKU 划出是设计建议，具体名单上线前核对。简单收货验收仍必需；采购在途不等于可售现货。后续若恢复缺货销售需新决策与测试，不暗中留开关。

这会降低首版业务和 UAT 复杂度，但不会免除支付验签、幂等、退款、库存竞争、隐私、恢复和运营责任。

## 与冻结 V1 的关系

[PROJECT_SPEC.md 第 35 节](../PROJECT_SPEC.md#35-future-commerce-migration-path) 要求未来销售先评估成熟平台，并列 A/B 为优先方向。这里保留三路线的文档级比较，明确记录用户选择偏离该优先建议；并未完成 Shopify 商家试店，也不把比较记成平台实测认证。**Shopify 试用不是继续规划或实施 C 的前提。**

V1 是目录站的历史规格，第 40 节“不含结账”等边界仍描述 V1。本文作为后续商业阶段的决策增量，不声称 V1 本来就批准 C；本轮不改 `PROJECT_SPEC.md`，也保留其已有未提交改动。若后续需要在规格入口说明演进，明确修订建议是：仅增加“后续商业阶段按 ADR-001，V1 历史范围不变”的交叉引用；不要重写第 35/40 节为当年已决定自建商城。

## A/B/C 比较记录

以下是架构与成本责任比较，不是商家资格、组合能力或最新报价的保证；A/B 细节仍需实际套餐、应用和账户核验。

| 维度       | A：完整 Shopify                                         | B：现有前台 + Shopify                                    | C：现有前台/Admin + 托管支付（已选）                                               |
| ---------- | ------------------------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 顾客体验   | 主题与平台结账，现有设计需迁移                          | 保留定制前台，商业结账交给平台，验证跳转/会话衔接        | 保留前台，本站报价/订单，服务商托管付款；自行保证返回和异常体验                    |
| 小姨操作   | 学习平台后台及必要应用                                  | 同样主要操作平台后台，明确自建 Admin 的退役范围          | 继续使用扩展 Admin；订单、收货、退款和异常界面都需开发及 UAT                       |
| 一次开发   | 迁移内容、主题、配置和运营验证，通常自建流程最少        | 加商品/API/缓存/购物车集成和迁移，保留前台并不等于少集成 | 模型、迁移、库存、两套支付适配、售后及恢复工具最多                                 |
| 持续维护   | 商家配置与应用/主题维护，平台承担较多通用商业能力       | A 的责任加自建前台与 API 同步维护                        | 团队承担状态正确性、升级、安全、监控、事件恢复和持续支持                           |
| 权威来源   | 平台商品、库存、订单；支付服务商交易/银行到账           | 平台为商业数据权威，D1 不再独立改库存或价格              | D1 为商业商品/库存/订单权威，服务商为在线支付交易事实权威，银行为到账依据          |
| 迁移与退出 | 导入真实 SKU/图片/政策，核验平台数据导出及主题/应用依赖 | 同 A，额外处理 ID 映射和前台接口；不得双写两份库存       | 保留目录并扩展模型，仍需真实数据建档；退出要迁移未履约订单、退款关联、库存账及审计 |
| 费用组成   | 订阅、支付、应用、主题、域名、迁移和运营时间            | A 的费用加 Workers/D1/R2、集成维护                       | 两家支付手续费、退款/争议/汇兑相关费用、基础设施、邮件、监控备份、开发和支持时间   |
| 主要风险   | 平台/应用限制、方案费用及迁移依赖                       | 双系统边界、同步失败、API 变更与更复杂排障               | 错收款/超卖/漏通知/不可恢复等由团队兜底；免平台订阅不等于总成本更低                |

平台资料入口：[Shopify Admin](https://help.shopify.com/en/manual/shopify-admin)、[Storefront cart](https://shopify.dev/docs/storefronts/headless/building-with-the-storefront-api/cart/manage)、[草稿订单](https://help.shopify.com/en/manual/fulfillment/managing-orders/create-orders/create-draft)。仅作为未来核对与比较资料，不是当前行动清单。

费用不在本 ADR 固化数字或沿用旧草案算例。上线预算由你与小姨记录实际所选产品、计费币种、税费、支付方式、退款/争议、国际卡/汇兑、应用和维护工时，并注明核对日期。官方入口：[Shopify 加拿大定价](https://www.shopify.com/ca/pricing)、[Stripe 加拿大定价](https://stripe.com/en-ca/pricing)、[PayPal 加拿大商业费用](https://www.paypal.com/ca/business/paypal-business-fees?locale.x=en_CA)。本轮未用商家账户核验报价。

## 承担责任与重新评估条件

- 小姨：供货和商品真实性、经营政策、账户、订单异常、退款授权与日常对账；会计/专业人士协助适用要求。
- 你：范围、预算、持续维护人和替班安排，接受 C 相对 A/B 增加的开发与退出成本。
- 开发者：数据约束、安全、支付事件与失败恢复、发布/回滚、告警、依赖升级和运维交接。不能把长期支持默认成无人负责的免费工作。

若无法落实维护人、实际费用超出预算、库存/支付关键不变量不能通过测试、小姨无法独立完成 UAT，或账户/产品资格无法支持必需支付方式，则暂停进入下一门槛并重新比较缩减范围或 A/B。改变已选架构要另记决策并说明迁移代价；不得在任务列表中悄悄恢复“Shopify 优先”。
