# C01：首版现货模型与安全契约

设计基线：2026-10-18；状态核对：2026-10-26。后续商业阶段，冻结 V1 不改写；已选 C，仅售验收现货。此契约支持可逆本地开发，不授权真实收款。已合并功能基线 `7558a17`，下方完整状态表仍是目标；实际本地子集和增量分别标注。

## 权威与边界

- `products` 管原目录展示；新 `commerce_variants` 管 SKU、颜色、单一尺寸说明、CAD 整数分价格、商业启停和版本。商业接口不读取旧 price_cents/quantity 计算金额库存；启用商业变体后阻止旧 Admin 修改这些旧字段。全量目录迁移不在首批任务内。
- `commerce_inventory` 管合格实物 on_hand、facebook_reserved、checkout_reserved、allocated。可售 = on_hand - 三种占用，所有值及结果非负。Facebook 留量只从可售划出，售出同时减实物和 FB 留量，不自动补留；不建立缺货销售模型。
- 库存账本记录唯一操作键、语义、数量变化及来源。SQL 触发器在插入账本后更新余额；约束失败使整条语句/整个 batch 失败。多行失败不得仅在提交后看 changes；请求重试必须比较原载荷，不能把同键不同数量当成功。
- 网站报价的所有商品/金额从变体和库存重新读，价格/费率变化需新报价。报价不锁库存；真正发起支付前创建持久订单并一次预留所有行。无真实支付账户时先用本地故障注入验证此边界。
- 默认关闭，商业测试入口仅显式 `COMMERCE_MODE=local-test` + loopback HTTP；不新增远程开启或 live 模式。现有 DB 绑定只可在 `remoteBindings:false`、临时本地持久目录中测试；测试不加载 `.env`/`.dev.vars`。
- 托管支付服务商是交易事实来源，网站 D1 是订单与库存权威。不能由浏览器返回成功、截图或任意本地模拟事件伪装正式已付款。

## 模型接口与不变量

| 对象        | 首批接口约束                                                                                     | 后续实现边界                                                          |
| ----------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| Variant     | string id/SKU；productId；colour；sizeDescription；priceCents；CAD；active；version              | 真实数据上架须验真，测试样例虚构，不复制300件样品为可售库存           |
| Inventory   | 安全整数，单次数量有上限；动作带 operationId                                                     | 收货、FB留/售/调回、结账预留/释放/确认/交付；移库不抢已锁货           |
| Quote       | 输入仅 variantId/quantity + 交付方式；输出版本化明细、subtotal/shipping/tax/total、CAD、testOnly | 请求中的价格/税率/合计不可作为权威；duplicate SKU、未知/停用/缺货拒绝 |
| Order       | pending_payment → confirmed → closed；cancel_requested/cancelled                                 | 不依赖单一状态承载付款和交付；保留购买时快照                          |
| Fulfillment | ready_to_pack → packed → pickup/delivery/shipped → completed；异常 held                          | 只有付款确认且有分配可履约；无常规 waiting_stock                      |
| Payment     | initiated/action_required/approved/processing/succeeded/failed/cancelled/expired/unknown         | approved 不等于 capture；同订单不同时发起两渠道尝试；unknown先查询    |
| Refund      | requested/pending/unknown/succeeded/failed                                                       | 成功+未定退款占用可退余额；不自动入库；独立授权、幂等、查询           |

付款成功把临时预留转为已确认分配，不再扣实物；交付同时减实物和分配。预留过期后迟到付款先 held，仅能按原约定重取网站空闲库存，不能占 FB 留量或变成进口预订。退款/取消/交付并发以数据库版本或条件约束裁决。Webhook inbox/事务去重及通知 outbox 在后续持久订单任务中实现，不将现有产品创建幂等当作支付幂等。

库存基础服务暂时仅供内部测试：汇总预留/分配余额不证明订单所有权；在持久 order_line/reservation 绑定实现之前，不公开按任意 SKU/数量释放、确认或发货的接口。独立审查要求账本和 command 拒绝 UPDATE/DELETE 及 REPLACE 改写身份。

## 明确的测试假设

- 仅 CAD，游客，单一履约地；虚构项链颜色样例，无真实顾客资料。
- 本地报价：pickup 0 分、local_delivery 500 分、shipping 1500 分；税率测试值 0 basis points。**全部虚构、不可用于营业或解释加拿大税务**。每个报价返回 `testOnly: true` 与规则版本，页面常驻测试提示；后续真实规则需经营/专业核对。
- 单行最多 20 件、购物车最多 20 行、报价有效期建议 10 分钟，预留期限后续与实际服务商验证。限制只是测试策略，可逆调整，不作为公开经营政策。
- 无采购 ERP、缺货预售、会员、定金/尾款、FB完整订单。FB仍需最小售出登记及实物核对，完整财务另记。

## 必须证明的异常路径

1. 相同 SKU 同时买最后一件：只有一个预留成功；多行中第二行不足，第一行及账本/订单都不残留。
2. 5件金色留1给FB，网站最多4；FB售出后网站仍4；重复售出请求只记一次；不同载荷重用键拒绝。
3. FB补留与网站结账竞态不抢已锁货；仅FB剩货时网站拒绝，其他颜色仍可买。
4. 缺/错环境、远程Host、伪造Forwarded、跨站Origin均不能启用/写入；Admin保护不弱化。
5. 价格/数量篡改、负数/浮点/溢出、重复行、停用/隐藏商品拒绝；报价不修改库存。
6. 支付前报价过期/金额变化需重确认；支付未知、重复/延迟事件、退款超时由持久记录恢复，不重扣/重退。

本地D1和模拟测试可证明约束/故障行为，不能证明服务商Sandbox、真机Safari、商家UAT或正式结算。

## 首批本地实现范围（2026-10-19 历史）

上面的完整状态表是后续目标；当前迁移只支持未支付订单 `pending_payment` → `cancelled`，支付初态 `not_started`、履约初态 `none`。`processing`/`unknown` 保留为防误释放的保护状态，尚无支付入口。没有确认收款、退款或发货的公开命令。

报价持久化但不锁库；同一报价只能生成一张订单，订单行触发器与订单/命令在同一 D1 batch 中原子预留。取消/内部到期命令从订单自己的行生成释放记录，并在数据库中复核版本、订单状态和付款未开始；拒绝以任意 SKU 释放他人的预留。本地浏览器会话只存随机 cookie，库中存 hash；所有读写订单按 owner 限制。内部通用库存命令仍不对外开放。

本地报价 10 分钟，未支付预留 15 分钟，均为测试常量。到期释放函数已有测试，但无后台定时任务。PR 3 的 `/commerce-lab` 通过高熵 HttpOnly 测试 Cookie 派生 owner hash，接入报价、预留、按 owner 查询最近 20 笔订单及手动取消；默认公开环境不可访问。Cookie 丢失后无恢复入口，日期到期本身不会释放库存。支付接入前必须补齐可靠期限任务、未知付款对账和 session 丢失恢复。不能把当前数据库中的保留状态或内部库存动作视为完整商业状态机。

### C06b1a 增量（2026-10-21）

新增内部有界到期批处理，逐笔复用已有释放事务；默认10单、最多25单，稳定游标分页，失败保留预留并可继续后页/新轮重试。中断后可从持久订单重新扫描，不依赖内存完成进度。0006 迁移加强到期转换触发器并加到期扫描部分索引：写入时履约必须仍为 `none`，不会自动处理 `held`；手工取消规则不变。服务层同样拒绝自动到期释放异常履约。扫描后开始付款/出现异常、重复任务/取消、失败回滚和本地运行时重启均有实际 D1 测试。
